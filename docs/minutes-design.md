# 議事録機能 設計書

作成日: 2026-09-30 / 状態: 設計案 第 2 版（実装前）

第 2 版で変えたこと: 開発コンソールに、ユーザーごとの利用状況の一覧を追加した（§7.2）。

名刺管理アプリに組み込む機能。ログイン、ユーザー、部署、開発コンソールの土台は [design.md](./design.md) のものを使う。費用は [cost-estimate.md](./cost-estimate.md) の §11。

## 1. 目的と範囲

商談や会議を録音し、文字起こしと議事録を作る。誰と話したかを、名刺と自社のユーザーに紐づけて残す。

| 作るもの | 作らないもの |
| --- | --- |
| 録音（ウェブ会議 / その場の音声）、最長 2 時間 | 採点、フィードバック、レーダーチャート |
| 文字起こしと議事録の作成、再生成 | 相手ごとの顧客メモの自動更新 |
| 名刺・自社ユーザーとの紐づけ | 利用枠、月ごとの集計、課金 |
| 選んだ相手への共有 | 会議の種類ごとのプロンプトの出し分け |
| 名刺の情報で絞れる一覧 | 文字起こしの本文の全文検索 |
| 音声のダウンロード（1 週間） | 議事録の手での書き換え（§12） |

## 2. sales-recorder から使うもの

`Assist-inc-net/sales-recorder`（商談まとめるクン）を読んで仕分けた。土台（ログイン、データの持ち方、基盤の定義）が名刺管理アプリと違うので、**リポジトリごと持ってくるのではなく、部品を移す。**

| 分類 | 対象 | 理由 |
| --- | --- | --- |
| そのまま使う | プロンプトの差し込み（`{{PARTICIPANTS}}` など）、モデルごとの設定値の検証、議事録の Markdown 表示 | 要件に合っていて、土台に依存しない |
| 直して使う | マイクの録音、Gemini での文字起こし、OpenAI での要約、共有、状態の表示 | 動いているが、下の表の穴をふさぐ必要がある |
| 新しく作る | ウェブ会議の録音、録音の途中保存、音声の分割、再生成、自社の同席者の紐づけ、音声のダウンロードと 1 週間での削除 | 実装が無い |
| 使わない | パスワードと TOTP のログイン、招待メール、複数組織の管理、利用枠と月次リセット、フィードバック、顧客メモ、会社・担当者の登録（名刺のデータに置き換える） | 名刺管理アプリの仕組みに置き換わる、または要件に無い |

**直す穴**

| sales-recorder の現状 | 起きること | この設計での対応 |
| --- | --- | --- |
| 録音を全部メモリに溜め、止めた後に 1 回で送る | 2 時間録音して最後に失敗すると、全部失う | 10 分ごとに区切って、その都度送る（§4.3） |
| 音声を丸ごと Gemini に渡し、1 回で全文を出させる | 2 時間だと出力の上限（65,536 トークン）にぎりぎりか、超える。超えると途中で切れ、気付けない | 区切りごとに文字起こしする。途中で切れたかを毎回確かめる（§5.2） |
| 失敗しても「成功」として終わる | 再試行が働かない。時間切れだと「処理中」のまま止まる | 区切りごとに結果を保存し、失敗した所からやり直す。20 分動きが無ければ失敗として扱う（§5.4） |
| 再生成が無い | やり直すには録音し直すしかない | 文字起こしと議事録を、それぞれボタンでやり直せる（§6） |
| 文字起こしは Gemini、要約は OpenAI に固定 | 入れ替えられない | 用途ごとに、どちらの系統のモデルも選べる（§7） |
| API キーは AWS の設定に直接置いてある | 画面から変えられない | 開発コンソールから登録する（§7） |
| 音声の形式を `audio/mp4` に固定 | Chrome で録音した音声（webm）を正しく扱えない | 録音した形式をそのまま記録して渡す |
| 管理者は、共有されていなくても組織内の全件を読める | 「選んだ相手にだけ」にならない | 役職による閲覧を無くす（§8） |
| 自社の同席者は名前の自由入力 | ユーザーと紐づかない | ユーザーの一覧から選ぶ（§9） |
| 音声は 30 日で削除。ダウンロードは無い | 要件と違う | 7 日で削除。ダウンロードを付ける（§6） |

## 3. 画面

```text
/                      名刺を探す（下段に「議事録を作る」「議事録の一覧」）
/minutes               議事録の一覧
/minutes/new           録音の種類を選ぶ → 録音
/minutes/:id           議事録（議事録 / 文字起こし / 音声）
/developer             開発コンソール（API キー、モデル、プロンプトに議事録の分を追加）
```

### 3.1 入口

名刺管理アプリの最初の画面（名刺を探す）の下段に置く。

```text
┌──────────────────────────────────────────────┐
│ 会社名 [        ]  氏名 [        ]  [検索]     │
│ ▼ その他の条件で絞る                           │
│  … 名刺の一覧 …                               │
├──────────────────────────────────────────────┤
│  [ 🎙 議事録を作る ]      [ 議事録の一覧 ]      │
└──────────────────────────────────────────────┘
```

スマホでは画面の下に固定して、名刺の一覧をスクロールしても押せるようにする。

### 3.2 録音

```text
┌──────────────────────────┐  ┌──────────────────────────┐
│  ウェブ会議を録音          │  │  ここの音声を録音          │
│  パソコンから出る音と       │  │  この端末のマイクで        │
│  マイクの音を録音します     │  │  その場の音を録音します     │
└──────────────────────────┘  └──────────────────────────┘
```

| | ウェブ会議を録音 | ここの音声を録音 |
| --- | --- | --- |
| Windows の Chrome / Edge | ○ 画面全体を選べばパソコン全体の音、タブを選べばそのタブの音 | ○ |
| Mac の Chrome / Edge | ○ タブの音。パソコン全体の音は新しい版の組み合わせだけ（§13） | ○ |
| Firefox、Safari（パソコン） | × ブラウザが音の取得に対応していない | ○ |
| iPhone、Android | × | ○（iPhone は Safari） |

使えない組み合わせでは、ボタンを押せない状態にして理由を出す。

**ウェブ会議を録音**

1. 手順の案内を出す。「次の画面で、会議のタブか画面全体を選び、『音声も共有する』をオンにしてください」
2. ブラウザの共有の画面で、利用者が選ぶ。
3. 音が共有されているかを確かめる。されていなければ録音を始めず、やり直しを案内する。
4. マイクの許可を取り、パソコンの音とマイクの音を 1 本に混ぜて録音する。
5. 録音中は、パソコンの音とマイクの音の大きさを別々に表示する。片方が無音のままなら知らせる。

- 映像は取得するが、保存も送信もしない（ブラウザの仕組み上、音だけの共有はできない）。
- 利用者がブラウザ側で共有を止めたら、「マイクだけで続ける」「録音を終える」を選ばせる。
- スピーカーで会議の音を出していると、マイクがその音も拾う。イヤホンを使うよう案内する。

**ここの音声を録音**

- マイクの許可を取って録音する。
- スマホは、画面が消えると録音が止まる。録音中は画面を消さないようにし、「画面をつけたままにしてください」と出す。
- 電話の着信などで録音が止まったら、そこまでを保存し、戻ってきたときに「再開する」を出す。

**共通**

```text
  ● 録音中   00:42:18   （最長 2:00:00）
  ▁▃▅▇▅▃▁  パソコンの音      ▁▂▃▂▁  マイク
  40 分まで保存済み
  [ 一時停止 ]   [ 録音を終える ]

  タイトル       [                              ]
  商談の相手     [ 名刺から選ぶ ]   株式会社アシスト 山田 太郎 ×
  自社の同席者   [ ユーザーから選ぶ ]   佐藤 花子 ×
  メモ           [                              ]
```

- 1 時間 50 分で「あと 10 分で録音を終えます」と知らせ、2 時間で自動で終える。
- 相手と同席者は、録音中にも入力できる。録音を終えた後でもよい。
- 録音の前に、「録音することを相手に伝えてください」と出す。

**ウェブ会議の共有の選び方（2026-10-02 追加）**

- 「共有を選んで録音を始める」を押すと、まず大きな注意を出す: 「次の画面で『システム音声も共有する』に必ずチェックを入れてください」。共有の選択画面の見本（画面全体が選ばれ、チェックが入った状態）を添える。チェックを忘れると相手の声が入らない録音になるため。
- 共有の選択画面は「画面全体」が最初に選ばれた状態で開く（`displaySurface: 'monitor'`）。タブや窓を選ぶと会議アプリの音が入らないことがあり、画面全体 + システム音声が一番確実なため。自分のブラウザのタブは選択肢から外す。

**ウェブ会議の録音中のマイクのオン・オフ（2026-10-07 追加）**

- 録音中の画面に「マイクをオフにする / オンにする」のボタンを置く。録音は止めず、マイクの音量だけを 0 にする（相手の声＝パソコンの音は録り続ける）。社内の打ち合わせ中の雑談を残したくないとき、咳払いのときなどに使う。
- ミュート中はボタンとマイクのメーターを赤・灰色にし、「マイクをミュートしています」を出す。メーターはマイクの生の音を見るので、ミュート中に話していると（直近約 1 秒の半分以上で声が出ていると）「いま話している声は録音されていません」を出し、その場でオンに戻せる。
- 切り替えの瞬間の「プツッ」という音を避けるため、音量は 15 ミリ秒かけて変える。
- 「ここの音声を録音」（スマホ）はマイクしか録らないので、このボタンは出さない（止めたいときは一時停止を使う）。

### 3.3 録音を終えてから

```text
① 録音を終える → ② 相手と同席者を確かめる → ③ [議事録を作る] → ④ 待つ → ⑤ 表示
```

| 段階 | 画面 |
| --- | --- |
| ② | 録音中に入れた内容が入っている。足りなければ足す。相手の名前は文字起こしに使う（話している人の名前、会社名の表記） |
| ③ | 押すと作成が始まる。「あとで作る」も選べる（録音は保存済み） |
| ④ | 「文字起こし中（3 / 12）」「議事録を作成中」と進み具合を出す。画面を閉じてもよい。一覧に状態が出る |
| ⑤ | 議事録を表示する |

2 時間の録音で、作成にかかるのは数分。

### 3.4 議事録の画面

```text
  株式会社アシスト 定例                       2026-10-02 14:00　1 時間 12 分
  相手:   株式会社アシスト 山田 太郎（営業部）  → 名刺を開く
  同席:   佐藤 花子、鈴木 一郎
  共有:   鈴木 一郎、田中 次郎                 [ 共有する ]

  ( 議事録 )  ( 文字起こし )  ( 音声 )

  … 本文 …

  [ コピー ]  [ 議事録を作り直す ]  [ 文字起こしからやり直す ]
  音声: [ 再生 ]  [ ダウンロード ]   あと 5 日で削除されます
```

### 3.5 議事録の一覧

```text
  ( 自分が作った )  ( 共有された )  ( すべて )

  相手の会社名 [        ]   相手の氏名 [        ]   [ 名刺から選ぶ ]
  ▼ その他の条件で絞る
     自社の同席者 [ 選択 ▾ ]   期間 [    ]〜[    ]   タイトル [        ]   作った人 [ 選択 ▾ ]

  絞り込み中: [相手の会社名: アシスト ×]
  2026-10-02  株式会社アシスト 定例      山田 太郎（株式会社アシスト）   1:12   完了
  2026-09-25  株式会社アシスト 初回訪問   山田 太郎、川口 三郎            0:48   完了   共有された
```

- 絞り方は名刺の検索と同じ。会社名と氏名が基本、その他は折りたたみ、複数入れたら「すべて満たす」、効いている条件をチップで表示。
- 「名刺から選ぶ」で名刺を 1 枚選ぶと、その人との議事録だけになる。
- 名刺の詳細画面にも「この人との議事録」を出す。
- どちらも、出てくるのは自分が見られる議事録だけ（§8）。

**相手の選び方と検索（2026-10-02 追加）**

- 「名刺から選ぶ」は、会社名を入れるたびに取引先の一覧（`GET /api/companies`）を引き、会社 → 部署 → 人の順に畳んで出す。人を押すと選ばれる。氏名で探す欄も残す。名刺の無い相手の手入力は従来どおり。
- 一覧の検索は、相手の会社名を入れると同じ候補が出て、会社を選ぶとその会社の部署を選べる（`department` で絞る）。会社名・部署名の文字での部分一致も従来どおり効く。

## 4. 録音の仕組み

### 4.1 音の取り方

| 種類 | 取り方 |
| --- | --- |
| パソコンの音 | ブラウザの画面共有の仕組み（`getDisplayMedia`）で、音も一緒に取る |
| マイク | `getUserMedia`。雑音の抑制と、スピーカーの音の回り込みの抑制をオンにする |
| 混ぜ方 | ブラウザの中で 2 つの音を 1 本にまとめてから録音する |

### 4.2 形式と大きさ

| 項目 | 値 |
| --- | --- |
| 形式 | ブラウザが対応しているものを選ぶ。Chrome と Edge は WebM（Opus）、Safari は MP4（AAC） |
| 音質 | 32kbps、モノラル。話し声には十分 |
| 大きさ | 1 時間で約 14MB、2 時間で約 29MB |

### 4.3 途中保存

**10 分ごとに区切り、区切るたびに送る。**

```text
録音    ├── 区切り 1 ──┼── 区切り 2 ──┼── 区切り 3 ──┼─ …
端末    10 秒ごとに端末の中に保存（送り終えたら消す）
送信                  ↑ 送る         ↑ 送る         ↑ 送る
```

| 起きること | 失うもの |
| --- | --- |
| 録音中にブラウザが落ちた、電池が切れた | 送り終えた区切りは残る。送る前の分も、端末の中に 10 秒単位で残っているので、次に開いたときに「前回の録音が残っています」と出して送れる |
| 通信が切れた | 録音は続く。つながったときにまとめて送る |
| スマホで画面が消えた、電話がかかってきた | そこまでを 1 つの区切りとして保存する。再開すると次の区切りになる |

- 区切りは、それぞれ単独で再生できるファイルにする。1 つが壊れても、ほかの区切りに影響しない。
- 区切りの境目で、音が一瞬（1 秒未満）途切れることがある。

### 4.4 音声ファイルのアップロード（2026-10-02 追加）

録音の代わりに、手元の音声ファイル（iPhone のボイスメモの m4a、mp3、wav、会議ツールの録画 mp4 など）を上げて文字起こしする。

| 項目 | 内容 |
| --- | --- |
| 入口 | 「議事録を作る」の種類に「音声ファイルを上げる」を足す（ウェブ会議 / ここの音声 / ファイル） |
| 送り方 | 1 本のまま、署名付き URL（有効 1 時間）でストレージへ直接送る（API Gateway の 10MB 制限を通さない）。表示用にファイル名を区切りに残す（200 字まで。長さを概算した区切りには `durationEstimated` を付け、置かれた大きさから概算し直す）。進み具合を画面に出す |
| 長さ | 録音と同じ最長 2 時間（Cloudflare 版は 60 分・100MB、1 本のまま Gemini で 1 回で文字起こし。選択中のモデルが OpenAI のときも Gemini の初期値に切り替える。出力が途中で切れたら失敗にして「60 分以内に分けて上げてください」と出す）。大きさは 600MB まで（ボイスメモの「ロスレス」は 1 時間で約 500MB なので、超えたら圧縮を促す）。長さはブラウザで読む。読めない形式なら 0 を送り、サーバーが 64kbps 相当として概算する |
| 変換 | 利用者側では要らない。サーバーで 1 つの区切りとして持ち、文字起こしのときにモデルの上限（10 分）ごとに ffmpeg で分ける（§5.2 の「モデルごとの長さ」と同じ仕組み）。AAC（m4a / mp4）と mp3 は再エンコードせずにそのまま切る（数秒）。それ以外の形式と、切れなかったときは mp3 に変換して切る |
| 大きさの上限 | OpenAI の文字起こしは 1 ファイル 25MB までなので、区切りが 20MB を超えるときも分ける。大きさで分けるときは、1 つが 16MB に収まるように 10 分より短く切ることがある。再エンコードせずに切った区切りの時刻は、フレームの境目の都合で 1 秒未満ずれることがある |
| その後 | 録音と同じ。相手と同席者を選び、「議事録を作る」を押す。音声のダウンロードと 7 日での削除も同じ |
| 利用状況 | 録音時間として数える（`kind: recording`）。録音とアップロードは分けない |
| 話者 | 区切りごとに推定するので、§5.2 のとおり区切りをまたぐと食い違うことがある。これは録音と同じ |

## 5. 文字起こしと議事録の作成

### 5.1 流れ

```text
ブラウザ           Lambda「app」          Lambda「minutes」              Gemini / OpenAI
   │── 議事録を作る ──▶│── 依頼 ───────────▶│                                │
   │◀─ 受け付けた ─────│                    │── 区切り 1〜N を並行で ─────────▶│ 文字起こし
   │                  │                    │◀─ 結果（区切りごとに保存）────────│
   │  （待ち画面）      │                    │   つなげて 1 本にする             │
   │                  │                    │── 文字起こしの全文 ─────────────▶│ 要約
   │                  │                    │◀─ 議事録 ────────────────────────│
   │── 状態を確認 ─────▶│                    │   保存                          │
   │◀─ 完了 ───────────│                    │   ダウンロード用の音声を作る       │
```

### 5.2 文字起こし

| 項目 | 内容 |
| --- | --- |
| 単位 | 区切りごと（10 分）。同時に 4 つまで |
| 渡し方 | 区切りは 2.4MB ほどなので、リクエストに直接入れる。Gemini 側にファイルを預ける手順（sales-recorder の方式）は要らなくなる |
| 名前の手がかり | タイトル、相手の会社名と氏名、自社の同席者の氏名、メモをプロンプトに差し込む |
| 時刻 | 区切りの中での時刻を出させ、アプリ側で区切りの開始時刻を足して、通しの時刻にする |
| 途中で切れたか | 応答が上限で打ち切られていないかを毎回確かめる。切れていたら、その区切りをやり直す |
| モデルごとの長さ | モデルによっては、1 回に渡せる長さが 10 分より短い。その場合は、サーバー側で区切りをさらに短く分けてから渡す（§7） |

**話している人の名前について**

音声から人を判別する専用の仕組みは使わない。プロンプトで渡した名前と会話の内容から、モデルが推定する。区切りごとに推定するので、**区切りをまたぐと、同じ人の名前が食い違うことがある。** 名前が分からない場合は「話者 A」「話者 B」とする。

### 5.3 議事録

文字起こしの全文を、別のモデルに渡して作る。2 時間分でも 1 回で渡せる。

### 5.4 失敗したとき

| 状況 | 動作 |
| --- | --- |
| 混雑、一時的なエラー | 間隔を空けて 2 回まで自動で試し直す |
| 一部の区切りだけ失敗 | 成功した区切りの結果は残す。**[もう一度試す]** で、失敗した区切りだけをやり直す |
| 議事録の作成だけ失敗 | 文字起こしは残す。**[もう一度試す]** で、議事録の作成だけをやり直す |
| 20 分たっても進まない | 失敗として扱い、**[もう一度試す]** を出す |
| 拒否された（blocked）区切り | 数回やり直し、それでも駄目なら 4 等分して起こし、駄目な部分だけを「文字起こしできませんでした」の行にして続ける。安全フィルタは BLOCK_NONE で呼ぶ（商談の音声が誤って止まるのを防ぐ。それでも止まるのは Gemini 側の RECITATION などの判定）。止めた理由（finishReason / blockReason）はログに残す |
| API キーが無効、モデルが使えない | 「設定に問題があります。開発者に連絡してください」と出す。開発コンソールに警告を出す |

どの場合も、録音は保存されている。

## 6. 再生成と音声

### 6.1 再生成

| ボタン | やること | 使える期間 |
| --- | --- | --- |
| 議事録を作り直す | いまの文字起こしから、議事録だけを作り直す | いつでも |
| 文字起こしからやり直す | 音声から文字起こしをやり直し、続けて議事録も作り直す | **音声が残っている 7 日間だけ** |

- 作り直している間は、前の内容を表示したままにする。新しいものができたら入れ替える。
- 1 つ前の内容を残しておき、「前の内容に戻す」で戻せる。
- 相手や同席者を直してから作り直すと、直した名前が反映される。
- 押せるのは、その議事録を作った人だけ。

### 6.2 音声のダウンロードと削除

| 項目 | 内容 |
| --- | --- |
| ダウンロード | 区切りをつなげて 1 本にしたものを渡す。形式は M4A（スマホでもパソコンでもそのまま再生できる） |
| 期限 | 録音を終えてから 7 日 |
| 期限を過ぎたら | 再生とダウンロードのボタンを消し、「音声は削除されました」と出す。文字起こしと議事録は残る |
| 期限が近づいたら | 「あと 2 日で削除されます。文字起こしのやり直しもそれまでです」と出す |

**削除の仕組み**

- アプリは、録音を終えた時刻から 7 日を過ぎたら、その時点で音声を渡さない。
- 実際にファイルを消すのは S3 の機能（保存期間の設定）。S3 は日単位で動くので、消えるのは 7 日から 8 日の間。
- 音声は、ほかのデータとは別の入れ物（バケット）に置く。過去の版を残す設定を付けず、消したものが残らないようにする。
- 文字起こしのために Gemini や OpenAI に送った音声は、リクエストの中に入れて渡すので、相手側にファイルとして残らない（不正利用の確認のための記録は別。[cost-estimate.md](./cost-estimate.md) §11）。

- 日時: {{DATE}}
- 相手: {{COUNTERPARTS}}
- 自社の同席者: {{ATTENDEES}}

担当、内容、期限。期限が話に出ていなければ「期限の話なし」。

**使い方**

- 期間は月単位で選ぶ。初期値は今月。
- 列の見出しを押すと、その列で並べ替える。初期値は録音時間の多い順。

- 一番下に合計を出す。
- 期間の中で一度も使っていない人は出さない。「使っていない人も出す」で全員を出せる。
- 無効になった人も、使った記録があれば印を付けて出す。
- CSV で出力できる。出力したことは監査ログに残す。

**見えるもの、見えないもの**

| 見える | 見えない |
| --- | --- |

議事録を見られるのは作った人と共有された人だけ、という決まり（§8）は、この画面でも変わらない。

**数え方の決まり**

- 利用は、その議事録を作った人の分として数える。再生成ができるのは作った人だけなので、ほかの人の分になることは無い。
- 議事録を削除しても、使った記録は減らさない。費用は既にかかっているため。
- 開発コンソールの「試し」で使った分は、試した開発者の分として、種類を「試し」にして数える。

## 8. 共有と、見られる範囲

**議事録を見られるのは、作った人と、共有された人だけ。役職は関係ない。**

| 人 | 見られるか |
| --- | --- |
| 作った人 | ○ |
| 共有された人 | ○ |
| 自社の同席者として紐づけられた人 | 共有されていなければ × |
| 役員、GM、SMG、MG、SubMG | 共有されていなければ × |
| 開発者 | 共有されていなければ ×。開発コンソールで見られるのは、誰がどれだけ使ったか（§7.2）と、状態・失敗の種類・消費トークン数だけで、タイトルと本文は見られない |

名刺は役職と部署で見える範囲が決まるが、議事録はそれとは別の決まりにする。

| 操作 | 作った人 | 共有された人 |
| --- | --- | --- |
| 議事録と文字起こしを読む | ○ | ○ |
| 音声の再生とダウンロード（7 日間） | ○ | ○ |
| 相手、同席者、タイトル、メモの変更 | ○ | － |
| 再生成 | ○ | － |
| 共有する、共有を取り消す | ○ | － |
| 削除 | ○ | － |

**共有の画面**

```text
  共有する相手を選ぶ                 [ 氏名や部署で探す        ]
  同席者から選ぶ:  (佐藤 花子)  (鈴木 一郎)
  ☑ 鈴木 一郎    営業部
  ☐ 田中 次郎    開発部
  ☐ 高橋 三郎    営業部;企画部
                                          [ 共有する ]
```

- 選べるのは、アプリに登録されていて、無効になっていない人。
- 同席者は、すぐ選べるように上に出す。自動では共有しない。
- 共有されると、相手の一覧に「共有された」の印が付いて出る。メールは送らない。
- 共有の取り消しは、すぐに効く。
- 共有と取り消しは、誰が・いつ・誰に、を記録する。

**名刺の見える範囲との関係**

議事録を共有された人が、相手の名刺を見られない部署の人である場合がある。

| 表示 | 扱い |
| --- | --- |
| 議事録に出る相手の会社名・部署名・氏名 | 見える。議事録の一部として、紐づけた時点の内容を写してある |
| 「名刺を開く」 | 名刺を見られる人にだけ出す。電話番号やメールアドレスは、名刺を見られる人にしか見えない |

## 9. 名刺と自社ユーザーへの紐づけ

| 紐づける相手 | 選び方 | 数 |
| --- | --- | --- |
| 商談の相手 | 名刺から選ぶ。会社名と氏名で探す。選べるのは、自分が見られる名刺 | 0 以上 |
| 自社の同席者 | ユーザーの一覧から選ぶ。氏名や部署で探す。作った人は最初から入っている | 1 以上 |

- 名刺がまだ無い相手は、会社名と氏名を手で入力できる。その場で「名刺を登録する」にも進める。後で名刺を登録したら、紐づけ直せる。
- 紐づけたときに、会社名・部署名・氏名を議事録の側にも写す。後で名刺が直されたり削除されたりしても、議事録の表示は変わらない。
- 紐づけは後から変えられる。変えても、文字起こしと議事録はそのまま（名前を反映したいときは再生成する）。
- 社内だけの会議は、相手を空にして、同席者だけを入れる。

## 10. データ設計

### 10.1 DynamoDB

名刺管理アプリと同じテーブルに足す。

| 種類 | pk | sk | 主な属性 |
| --- | --- | --- | --- |
| 議事録 | `MIN#<議事録ID>` | `META` | 下の表 |
| 区切り | `MIN#<議事録ID>` | `SEG#<番号>` | 音声のキー、形式、開始時刻、長さ、大きさ、文字起こしの状態 |
| 共有 | `MIN#<議事録ID>` | `SHARE#<メールアドレス>` | sharedBy, sharedAt |
| 見られる議事録 | `USER#<メールアドレス>` | `MIN#<日時>#<議事録ID>` | 関係（作った / 共有された）、一覧と絞り込みに使う項目の写し |
| 名刺との紐づけ | `CARD#<名刺ID>` | `MIN#<日時>#<議事録ID>` | なし |
| 利用量（ユーザーごと） | `USAGE#<年月>` | `MINUTES#USER#<メールアドレス>` | 録音の本数、録音時間、文字起こしと議事録の回数（初回 / やり直し）、失敗、文字起こしした音声の時間、トークン数、概算費用、最後に使った日時 |
| 利用量（モデルごと） | `USAGE#<年月>` | `MINUTES#MODEL#<モデルID>` | 回数、失敗、トークン数、音声の時間、概算費用 |
| 利用の記録 | `USAGE#<年月>` | `MINLOG#<日時>#<連番>` | 使った人、種類、録音時間、モデル、結果、失敗の種類、トークン数、概算費用。2 年で自動削除 |

- 利用量は、録音を終えたとき、文字起こしや議事録の作成が終わったときに、その月の数字に足していく。一覧を出すときに集計し直す必要が無い。
- 利用の記録には、議事録の ID もタイトルも入れない。開発コンソールから議事録の中身にたどれないようにするため。

**議事録の属性**

| 分類 | 属性 |
| --- | --- |
| 基本 | title, heldAt, mode（ウェブ会議 / その場）, durationSec, memo |
| 持ち主 | ownerEmail, ownerName |
| 相手 | counterparts（名刺 ID、会社名、部署名、氏名の配列。名刺が無い相手は名刺 ID が空） |
| 同席者 | attendees（メールアドレス、氏名、部署の配列） |
| 状態 | status, step, progress, failure, updatedAt |
| 音声 | segmentCount, audioExpiresAt, downloadKey, audioDeleted |
| 文字起こし | key, model, promptVersion, version, createdAt, previousKey |
| 議事録 | key, model, promptVersion, version, createdAt, previousKey |

**状態**

| 状態 | 意味 |
| --- | --- |
| 録音中 | 区切りを受け取っている |
| 作成待ち | 録音は終わった。「議事録を作る」を待っている |
| 文字起こし中 / 議事録を作成中 | 処理中 |
| 完了 | 読める |
| 失敗 | どの段階で失敗したかを持つ。「もう一度試す」を待っている |

**一覧の出し方**

「見られる議事録」を、その人の分だけ読む。1 人が見られる議事録は多くても数百件なので、全部読んでから条件で絞る。名刺の検索のような、全件をメモリに持つ仕組みは要らない。

- 共有すると、相手の「見られる議事録」に 1 件足す。取り消すと消す。
- タイトルや相手を変えたら、見られる人全員の写しを書き換える。

### 10.2 S3

| バケット | キー | 保存期間 |
| --- | --- | --- |
| 音声 | `minutes/<議事録ID>/seg-<番号>.webm` または `.m4a`、`minutes/<議事録ID>/audio.m4a` | **7 日で削除** |
| 文章 | `minutes/<議事録ID>/transcript-v<版>.txt`、`summary-v<版>.md`、区切りごとの文字起こし | 議事録を削除するまで |

- 音声のバケットは、過去の版を残す設定を付けない。
- 議事録を削除すると、音声、文章、紐づけ、共有をすべて消す。

## 15. 資料（PDF / PowerPoint / Excel）を踏まえた議事録

追加日: 2026-10-01。会議で使った資料を議事録に添付し、**資料と文字起こしの両方**から議事録を作り直せるようにする。「このスライドの話はここ」という対応付けを行い、グラフだけで語られた箇所も拾う。

### 15.1 方針

| 論点 | 決め |
| --- | --- |
| ファイルの変換 | **サーバーでは変換しない。** PDF はそのままモデルに渡す（ページを画像として読める。グラフも読む）。pptx / xlsx は**ブラウザで zip を展開**し、文字（本文、発表者ノート、セルの値）と**グラフの元データ**（系列名、項目、値）を抜いて JSON にする。LibreOffice のようなサーバー側の変換は持たない（無料プランの Worker では動かない。要るなら Containers / Lambda コンテナで後から足す） |
| グラフ | ネイティブのグラフは元データを数値のまま渡す（画像を読むより正確）。画像として貼られたグラフは pptx からは読めないので、「図が重要なら PDF も添付」と案内する |
| 要約のモデル | 「議事録」用に選んであるモデルを使う。GPT なら PDF を OpenAI の Files API に預けて `input_file` で渡し、Gemini なら Files API に預けて `fileData` で渡す |
| 対応付け | 2 段階。(1) 資料をページ単位の「目次」にする。(2) 目次 + 文字起こし（時刻付き）から、「時刻の範囲 → ページ」の対応表と議事録を 1 回の呼び出しで JSON として出させる |
| 見られる範囲と削除 | 議事録と同じ（作った人と共有された人）。議事録を削除すると資料も消える。音声と違って 7 日では消さない |

### 15.2 画面

議事録の詳細に「資料」の欄を足す。

```text
  資料                                           [ 資料を追加 ]
  📄 提案書_v3.pdf      18 ページ   目次: 作成済み      [開く] [削除]
  📊 売上推移.xlsx       2 シート    グラフ 3 つ         [開く] [削除]

  [ 資料を踏まえて議事録を作り直す ]
  ※ PowerPoint の図が重要なときは、PDF で書き出したものも添付してください
```

- 受け付けるのは PDF / pptx / xlsx。1 件 50MB、1 つの議事録に 5 件まで（2026-10-02 に 20MB から引き上げ）。PDF が 14MB 以上のときは Gemini の Files API に預けてから読ませる（リクエストに直接入れられるのは 20MB までで、base64 で 1.33 倍になるため）。
- 追加の流れ: ファイルを選ぶ → ブラウザで展開（pptx / xlsx）→ 元のファイルと抜いた JSON を送る → 一覧に出る。PDF は元のファイルだけ送る。
- 「資料を踏まえて議事録を作り直す」で新しい版ができる。前の版には既存の「前の内容に戻す」で戻れる。資料を踏まえた版には印が付き、対応表（スライド → 時刻）が議事録の下に出て、押すと文字起こしのその時刻に飛ぶ。
- 共有された人は資料を見られる（開ける）が、追加・削除・作り直しはできない。

### 15.3 ブラウザでの展開

pptx / xlsx は zip + XML。ブラウザ標準の `DecompressionStream('deflate-raw')` で展開でき、ライブラリは要らない。

| 形式 | 抜くもの | 出力（JSON） |
| --- | --- | --- |
| pptx | スライドごとの本文（`ppt/slides/slideN.xml` の `a:t`）、タイトル（タイトルのプレースホルダ）、発表者ノート（`ppt/notesSlides/`）、グラフ（`ppt/charts/chartN.xml` の `c:cat` / `c:val` のキャッシュ、系列名、グラフの種類、タイトル） | `{ kind: 'pptx', slides: [{ no, title, text, notes, charts: [{ type, title, categories, series: [{ name, values }] }] }] }` |
| xlsx | シートごとのセルの値（`xl/sharedStrings.xml` + `xl/worksheets/sheetN.xml`。数式は値だけ）、グラフ（`xl/charts/`） | `{ kind: 'xlsx', sheets: [{ name, rows: [[...]], truncated, charts: [...] }] }` |
| PDF | 何も抜かない（モデルが直接読む） | `{ kind: 'pdf' }` |

- セルは 1 シート 500 行 × 50 列まで。超えた分は `truncated: true` にして切る。
- 抜いた JSON は 1 件 2MB まで。超えたら本文を切り詰める。
- 対応していない形式（.ppt / .xls / .doc）は、保存し直してもらう案内を出す。

### 15.4 目次化（1 段目）

| 形式 | 目次の作り方 |
| --- | --- |
| PDF | モデルに PDF を渡し、ページごとに「見出し、要点、**図やグラフの説明文**（種類、軸、読み取れる値や傾向）、固有名詞」を JSON で出させる。100 ページを超える PDF は 50 ページずつに分ける（OpenAI の上限に合わせる） |
| pptx / xlsx | モデルを使わず、抜いた JSON から機械的に作る。本文とノートをそのまま、グラフは「系列 × 項目 = 値」の表の文字列にする |

目次の形: `{ sections: [{ page, title, summary, figures: ["棒グラフ: 横軸は地域、関東 120 / 関西 95 / 九州 40。関西だけ前年比で伸びている"], keywords: [...] }] }`

図の説明文を目次に持たせるのが要。文字起こしに「この伸びが」としか出なくても、2 段目がこの説明文を手がかりに対応付けられる。

### 15.5 対応付けと議事録（2 段目）

目次（全資料）と文字起こし（時刻付き）を渡し、JSON を 1 回で出させる。

```json
{
  "mapping": [{ "material": 1, "page": 7, "start": "00:12:10", "end": "00:18:40", "confidence": "high" }],
  "markdown": "## 要点\n…"
}
```

議事録（`markdown`）の形:

```text
## 要点
## 資料に沿った話の内容
### 提案書_v3.pdf  スライド 7「地域別売上」（00:12:10〜00:18:40）
  - 説明した内容、相手の質問と答え、決まったこと
## 資料に無かった話題
## 資料にあったが話していないページ
## 決まったこと
## これからやること
## 確認が必要なこと
```

- 「話は資料の順に進むことが多い」「資料に無い話が続く区間は無理に対応付けない」「確信が持てない対応は `confidence: low`」をプロンプトに書く。
- 2 時間の文字起こし（約 5 万トークン）+ 50 ページの目次（2〜3 万トークン）は 1 回で渡せる。費用は 1 回 $0.05〜0.1 程度（gemini-3.6-flash / gpt-6.1-sol）。
- プロンプトは開発コンソールで編集できる 2 本を足す: 「資料の目次化」（`outline`）と「資料を踏まえた議事録」（`summarize_materials`。差し込みは `{{MATERIALS}}` と `{{TRANSCRIPT}}` ほか）。出力の型（JSON スキーマ）は名刺と同じくコード側で固定する。

### 15.6 データ

| 置き場所 | 内容 |
| --- | --- |
| DynamoDB `MIN#<id>` / `MAT#<連番>`、D1 `minute_materials` | id, seq, name, kind, size, pages, key, extractKey, outlineKey, outlineStatus, uploadedBy, uploadedAt |
| 文章のバケット | `minutes/<id>/materials/<matId>.<ext>`（元のファイル）、`<matId>.extract.json`、`<matId>.outline.json`、`summary-mapping-v<n>.json` |
| 議事録の `summary` | `withMaterials`（真偽値）、`materialIds` |

### 15.7 限界

- 対応付けは推定。資料の順と違う順で話した、資料に無い話が長い、という場合は精度が落ちる（`confidence` で印を付ける）。
- pptx に画像として貼られたグラフ・図は読めない（PDF の添付で補う）。
- Excel の PDF 書き出しはページの区切りで崩れやすいので、Excel は xlsx のまま付けるのを基本にする。
- .ppt / .xls（古い形式）は対象外。

## 16. 議事録への質問（チャット）

追加日: 2026-10-01。議事録を開いた人が、その会議について LLM に質問できる。**渡すのは文字起こしと資料の内容。議事録（要約）は渡さない**（要約の解釈に引きずられず、元の発言と資料から答えさせるため）。

### 16.1 決め

| 論点 | 決め |
| --- | --- |
| 誰が使えるか | その議事録を見られる人（作った人と共有された人） |
| 会話の単位 | **利用者ごとに別のスレッド。** 同じ議事録でも、自分の質問と答えしか見えない。開発者も他人のスレッドは読めない |
| 渡すもの | 文字起こしの全文（時刻付き）、資料の目次（PDF は目次 JSON、pptx / xlsx は抜いた JSON から作った目次。§15.4 と同じ）、会議の情報（タイトル、日時、相手、同席者、メモ）、そのスレッドの直近 10 往復 |
| 渡さないもの | 議事録（要約）、対応表、ほかの議事録 |
| モデル | 用途「質問」（`qa`）として開発コンソールで選ぶ。初期値は議事録と同じモデル。系統は Gemini / OpenAI のどちらでも |
| プロンプト | 開発コンソールで編集できる 5 本目（`qa`）。差し込みは `{{TITLE}}` `{{DATE}}` `{{COUNTERPARTS}}` `{{ATTENDEES}}` `{{MEMO}}` `{{MATERIALS}}` `{{TRANSCRIPT}}` |
| 答え方 | 文字起こしと資料に書かれていることだけで答える。無ければ「文字起こしと資料には見当たりません」と言う。根拠の時刻（`[00:12:10]`）やページを添える |
| 応答 | 同期（質問を送ると答えが返る）。長い会議でも 10〜20 秒。API Gateway の 30 秒を超えたら失敗として表示し、もう一度送れる |
| 保存 | 質問と答えをスレッドに残す。利用者が「履歴を消す」で自分のスレッドを消せる。議事録を削除すると全員のスレッドも消える |
| 上限 | 質問は 1 回 2,000 字。1 人 1 日 200 回（名刺の読み取りと同じ考え方） |
| 利用量 | 用途 `qa` として利用者ごとに記録（§7.2 の一覧に「質問」の列を足す） |

### 16.2 画面

議事録の詳細に「質問」のタブを足す（議事録 / 文字起こし / 音声 / 質問）。

```text
  ┌──────────────────────────────────────────────┐
  │ 文字起こしと資料をもとに答えます（議事録は渡しません） │
  │                                              │
  │  ■ 値引きの話は出ましたか？                     │
  │                                                │
  │  ▢ はい。[00:41:20] 付近で、相手から「初年度だけ   │
  │    10% 下げられないか」という相談があり、こちらは   │
  │    持ち帰りにしています。資料のスライド 7 の料金表  │
  │    を見ながらの話でした。                        │
  │                                                │
  │ [ 質問を入力…                      ] [ 送る ]   │
  │ 履歴を消す                 モデル: Gemini 3.6 Flash│
  └──────────────────────────────────────────────┘
```

- 送信中は答えの欄に点滅する印を出し、入力欄は無効にする。
- 答えの中の `[HH:MM:SS]` は押すと文字起こしの該当行へ飛ぶ（対応表と同じ仕組み）。
- 文字起こしがまだ無い（作成前・失敗）ときはタブを出さない。

### 16.3 データ

| 置き場所 | 内容 |
| --- | --- |
| DynamoDB `MIN#<id>` / `CHAT#<利用者ID>#<連番 4 桁>`、D1 `minute_chats` | role（user / assistant）、text、modelId、inputTokens、outputTokens、createdAt |
| 利用量 | `kind: 'qa'`（1 往復で 1 件） |

スレッドの読み出しは `CHAT#<利用者ID>#` の前方一致。モデルに渡す直近の往復は最後の 20 件（10 往復）。
